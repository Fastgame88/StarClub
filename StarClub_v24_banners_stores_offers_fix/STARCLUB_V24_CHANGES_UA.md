# Star Club v24 — виправлення пропозицій, банерів і магазинів

Архів містить тільки файли, змінені для цього набору правок. Розпакуйте його в корінь чинного проєкту зі збереженням структури папок.

## Змінені файли

- `public/app.js` — компактні картки пропозицій; окреме завантаження керованих банерів; збережено перемикання між клубними та оптовими пропозиціями.
- `public/styles.css` — компактне оформлення пропозицій та більший текст кнопок «Усі / Нарахування / Витрати / Бонуси» в історії.
- `public/admin.js` — новий розділ керування банерами; виправлення фіксованої ціни для одного товару; «Усі магазини» або один магазин 1С; окреме відображення клубних та оптових полів; новий редактор даних магазинів; вилучення блоку ручного керування цінами по магазинах.
- `public/admin.css` — стилі банерного редактора, магазинів та розділених клубних/оптових полів.
- `public/index.html` — версія клієнтських ресурсів `v=24`.
- `public/admin.html` — пункт «Банери» та версія ресурсів `v=24` у мобільній адмінці.
- `public/admin-desktop.html` — пункт «Банери» та версія ресурсів `v=24` у ПК-адмінці.
- `src/db.js` — таблиця керованих банерів та безпечна автоматична міграція чинної бази.
- `src/index.js` — API банерів; показ магазинів із 1С; ціна загальної пропозиції за улюбленим магазином; підтримка значення «Усі магазини».

## Що виправлено

1. Картки пропозицій стали нижчими й чистішими: одна невелика плашка типу, коротка назва магазину, заголовок, один рядок опису, ціна/стара ціна/економія в одному блоці та компактна область фото праворуч. Дубль фіксованої ціни внизу прибрано.
2. У фільтрах історії збільшено розмір тексту.
3. В адмінці з’явився розділ «Банери»:
   - глобально увімкнути або повністю прибрати банерний блок;
   - створити власний банер;
   - взяти дані з клубної чи оптової пропозиції;
   - завантажити власне фото до 1 МБ або вставити URL;
   - змінити мітку, заголовок, опис, дію після натискання, порядок і активність;
   - редагувати та видаляти банери.
4. Блок «Ціни товарів по магазинах» прибрано з адмінки. Внутрішнє зберігання синхронізованих цін залишено, бо воно потрібне для правильного показу ціни улюбленого магазину.
5. У пропозиції можна вибрати «Усі магазини» або конкретний магазин зі списку 1С. У списку видно назву й код магазину.
6. Магазини автоматично надходять із чинної синхронізації номенклатури 1С. Коли є магазини 1С, демо-магазини не показуються в реєстрації. В адмінці код і назва приходять із 1С, а адресу, телефон, графік і фото можна доповнювати вручну; синхронізація ці поля не стирає.
7. Для правила «Усі магазини» стара й нова ціна в застосунку розраховуються від ціни улюбленого магазину клієнта.
8. Клубні й оптові поля в адмінформі розділені: при клубній ціні оптові рівні приховані та вимкнені, при оптовій — клубний спосіб ціни прихований та вимкнений. Клієнтські вкладки «Клубні» й «Оптові» залишилися окремими.
9. Виправлено помилку фіксованої ціни: заблокований список типу товару більше не губить значення `product`, тому один вибраний товар успішно зберігається.

## Важливо щодо 1С

Файли модуля 1С не змінювалися. Чинний endpoint `/api/1c/products/sync` уже приймає `store_external_id`/`store_id` та `store_name`, автоматично створює або оновлює магазин і записує окрему ціну товару для цього магазину.

Після deploy запустіть звичайну синхронізацію номенклатури Star Club у 1С. Після цього магазини з’являться:

- у виборі улюбленого магазину під час реєстрації;
- у розділі «Магазини» адмінки;
- у списку магазинів під час створення пропозиції.

## Після заміни

1. Замініть усі файли з архіву.
2. Зробіть commit/push і дочекайтеся deploy.
3. База оновиться автоматично під час запуску — окремі SQL-команди не потрібні.
4. Запустіть синхронізацію номенклатури в 1С.
5. Закрийте Mini App у Telegram і відкрийте повторно, щоб завантажилися файли `v=24`.

## Перевірено

- синтаксис `src/index.js`, `src/db.js`, `public/app.js`, `public/admin.js`;
- міграція нової та чинної бази даних;
- синхронізація двох магазинів і різних цін з 1С;
- ціна пропозиції відповідно до улюбленого магазину;
- створення фіксованої ціни для одного товару;
- API створення та показу банерів;
- DOM-smoke тести клієнтського застосунку й адмінки;
- розбір CSS без синтаксичних помилок.
